## Code Quality Observations

- **CSV parsing is pure and defensive.** `parser.ts` uses `PapaParse` (or equivalent), validates required columns, normalizes BOM/CRLF, and returns row-indexed, PII-safe errors.
- **Student flow router is clean and testable.** Dependency-injected `runPlacement` makes the pure branching logic easy to unit test without a live placement implementation.
- **Wizard state machine is straightforward.** Three steps (`create-class`, `upload`, `preview`) with clear data flow.
- **Some patterns could be tightened:**
  - The wizard uses `// eslint-disable-next-line @typescript-eslint/no-explicit-any` casts for the Convex API (`api as any`, `useMutation(... as any)`). This is pragmatic until `npx convex dev` runs, but it should be removed after codegen.
  - `handleCommit` sets `pendingCommit` state, which triggers a `useEffect` to call `importRoster`. This indirection exists because the mocked `useMutation` reads its handler at render time; in production the mutation could be invoked directly.
  - `organizationId` is in props but unused (reserved for future use).
- **Test coverage is strong.** Every production file has a corresponding test file, and adversarial coverage (46 tests) probes boundary cases.
