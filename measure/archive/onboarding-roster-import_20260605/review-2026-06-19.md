## 3. Code quality observations

- **Parser is robust:** BOM stripping, CRLF normalization, RFC-4180-ish quoted-field handling, row-level `missing_required`/`invalid_email`/`duplicate_identifier` errors.
- **Dry-run is pure and deterministic:** `dryRunPreview` computes counts without side effects.
- **Student router is dependency-injected:** `routeStudent` accepts `runPlacement` in `deps`, making it testable without a live placement engine.
- **Convex mutation has a scalability concern:** `importRosterMutation` calls `ctx.db.query('profiles').withIndex('by_username').collect()` to build an in-memory email→profile map. This is O(n) in the total profile table rather than a per-row lookup, but it is bounded by a single query.
- **Email validation inconsistency:** `parser.ts` uses a strict regex (`/^[^\s@]+@[^\s@]+\.[^\s@]+$/`), while `roster-import.ts` uses a substring check (`includes('@') && indexOf('@') < lastIndexOf('.')`). A row that passes the parser could still be rejected at import time, or vice versa.
- **Component casts:** `RosterImportWizard.tsx` and `ImportSummary.tsx` use `as any` for the Convex API until codegen runs. This is documented in the plan but is technical debt.

## 4. Risks or blockers

- **Low — email validation drift:** The parser and the Convex mutation use different email validity rules. Unify them behind a shared validator.
- **Low — `sisId`-only rows:** The parser now surfaces `missing_required` when a row has neither email nor sisId, but the enrollment mutation still requires email. The CSV contract says `email/identifier`, but `sisId` is not used for lookup. This is a gap relative to FR2/FR3 if SIS-only rosters are expected.
- **Low — `any` casts in UI components:** Should be removed after `npx convex dev` regenerates `api.d.ts`.
- **None severe.** No blockers for this track.
