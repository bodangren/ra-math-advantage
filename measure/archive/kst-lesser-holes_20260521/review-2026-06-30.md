## 3. Code quality observations

- **Strengths**
  - Schema refinements are precise: `.min(1)` plus `superRefine` gives early, descriptive failures for empty bands, duplicate ids, non-monotonic thresholds, and out-of-order snapshots.
  - Extracting `EDGE_ENDPOINT_RULES` to a canonical module removes a known drift vector between Zod refinement and runtime validation.
  - `projectDisplayLevel` now fails safely on invalid bands via `displayLevelSchema.parse(levels)` instead of relying on non-null assertions.
  - The IM3 CSV loader validates parsed rows before passing them downstream, preventing NaN and malformed-row propagation.
  - Stale Red-phase comment cleanup improves maintainability and prevents future readers from misinterpreting passing tests as expected-to-fail.

- **Concerns**
  - `LevelProjectionFn` is still typed as `(state: KnowledgeState) => string` (ADV-P6-N1). While marked non-blocking, the return type could be narrowed to a known level id to make domain projections type-safe.
  - `projectDisplayLevel` throws a `z.ZodError` on invalid bands, which is fine for internal use, but downstream callers may want a structured result rather than an exception.
  - The `transfers_to` consumption logic (prior on initial card stability) remains out of scope and is not yet implemented anywhere; dependent tracks should not assume it exists.
