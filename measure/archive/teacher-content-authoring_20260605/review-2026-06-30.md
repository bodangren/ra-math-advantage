## 3. Code quality observations

- **Strengths**
  - Pure, app-local modules with no side effects; easy to unit test.
  - Discriminated union return type (`NormalizeLessonDraftResult`, `ActivityConfigValidationResult`) gives callers type-safe error handling.
  - Stable ID derivation from position avoids UUID churn in tests and UI previews.
  - Sanitizer does not rely on `dangerouslySetInnerHTML`; the `SanitizedText` component emits a plain text node.
  - Review B found and fixed a wrapper-tag escape quickly, with a regression test.

- **Concerns**
  - The sanitizer is regex-based. While acceptable for the narrow Phase 1 scope, it is not a full HTML parser and could miss obfuscated payloads (e.g. `<scr ipt>`, HTML entities, null bytes, SVG event handlers). A future hardening pass should consider `isomorphic-dompurify` or a bounded parser before Phase 4 end-to-end verification.
  - `authoring-model.ts` silently drops activities/sections/phases that fail to normalize (it `return`s early without pushing). The final empty-container check catches the symptom, but the error path could accumulate more specific per-item diagnostics.
  - `validateActivityConfig` casts `result.data` to `Record<string, unknown>`; this is safe because `safeParse` already narrowed, but an explicit inferred type would be cleaner.
